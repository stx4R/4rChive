# AGDecision.

<p align="center"><img src="../assets/kr/AGDecision/cover.png" alt="AGDecision. 代表画像" width="100%"></p>

> 「アルゴリズムに基づく意思決定は本当に客観的か」を質問紙（15人）と面接（6人）で検証した「社会と文化」の探究。アルゴリズムが何を差別するかよりも、人々がその判定をなぜ疑わずに受け入れるのかに焦点を当てた

---

## 1. プロジェクト概要 (Overview)

| 項目 | 内容 |
|---|---|
| プロジェクト名 | AGDecision.（アルゴリズムに基づく意思決定の客観性の検証） |
| 一行要約 | 質問紙法と面接法を併用した混合研究で、アルゴリズムの信じ方に4つのパターンを見いだした：① 理解するほど信じなくなる ② わからないまま信じる ③ 高リスクの決定まで任せる ④ 「客観」と「公正」を区別する |
| 期間 | 2026.06（2年生「社会と文化」の実技評価（遂行評価）①・②） |
| 参加人数 | 個人での探究 |
| 本人の役割 | テーマ選定、文献調査、質問紙・面接の設計、データ収集、統計分析、レポート作成 |
| 貢献度 | 100% |

アルゴリズムは今や、コンテンツのおすすめだけでなく、採用の書類選考、信用評価、入試、再犯リスクの予測まで担っている。その背景には「AIは感情に左右されないから、人間より客観的だ」という通念がある。しかし、アルゴリズムは人間が積み上げたデータから学び、データに刻まれた差別も一緒に学んでしまう。

出発点は、自分が作った[HowTo](HowTo_README.md)だった。ごみの写真を判別するモデルは、撮影の角度・照明・背景が変わったり、学習データに少ない形のものが出てきたりすると、同じ物を別の種類に繰り返し誤分類した。ごみのようにリスクの小さい対象でも間違えるのなら、採用や融資のように人を判定するアルゴリズムはどうだろうか。その誤判定がランダムではなく、特定の集団に偏っていたらどうだろうか。この疑問を、「社会と文化」の教科で学ぶ省察的態度（目に見える現象の裏側を疑う態度）で掘り下げたのがこの探究である。

先行研究の多くは、アルゴリズムの**出力**が偏っていることを示してきた。この探究は、その差別が**なぜ疑われずに受け入れられるのか**を、利用者の認識の側から説明する。

## 2. 技術スタック (Tech Stack)

社会科学の探究なので、コードの代わりに研究方法と分析ツールを記す。

| 区分 | 方法・ツール | 選定理由 |
|---|---|---|
| 研究デザイン | 混合研究（量的 + 質的） | 質問紙で「何が起きているか」を、面接で「なぜそうなるのか」を見て、互いの隙間を埋める |
| 量的データ | 質問紙法：18問 · 6領域 · 5段階尺度（同学年の15人） | 客観性に対する抽象的な態度 → 領域ごとの信頼 → 偏りの認知とのギャップ、という順で段階的に測る |
| 質的データ | 面接法：半構造化（6人） · 共通質問4つ + 傾向別の深掘り質問 | 数値の裏にある判断の論理を引き出す |
| 分析 | 平均の比較、相関係数、クロス集計、マン・ホイットニーのU検定 | 標本が小さく正規性を仮定しにくいので、ノンパラメトリック検定を使った |
| 文献 | キャシー・オニール『大量殺傷数学兵器』（Weapons of Math Destruction）、ProPublica COMPAS、Gender Shades、アマゾンのAI採用、「社会・文化」の教科書 | 認識調査では直接測れない「出力の差別」を事例で補う |

## 3. 主な機能と担当業務 (Key Features & Contributions)

### 質問紙の設計（15人 · 18問）

| セクション | 領域 | 測定内容 |
|:---:|---|---|
| 0 | 基本情報 | 性別 · AIの利用時間 · コーディング経験 |
| 1 | 客観性の認識 | 「AIは人間より客観的か」「感情や偏見がなく公正か」 |
| 2 | 領域ごとの信頼度 | 採用 · 融資 · 入試 · 再犯予測 · コンテンツのおすすめ |
| 3 | 偏り・差別の認知 | 特定の集団に不利に働く可能性、差別事例を知っているかどうか |
| 4 | 認識のギャップ | 「偏りを知りながらも信頼するか」「差別的なら修正されるべきか」 |
| 5 | 自由回答 | 信頼・不信の理由を一文で |

### 面接の設計（6人）

共通質問4つ（AIをどの程度信頼するか、客観性に同意するか、意思決定の過程を理解しているか、特定の集団が差別される可能性）を先に尋ね、回答の傾向に応じて深掘りの質問を変えた。回答者は3つのタイプに分かれた。

| タイプ | 中心となる論理 |
|---|---|
| 部分信頼型（2人） | **消去法的な信頼。**「私心のないAIのほうが、不透明な人間の主観よりは確率的にましだ」。使う理由も、信頼というより責任回避と利便性に近い |
| 強い信頼型（2人） | **統計的な最適解。** 膨大なデータの平均が個人の偏見をふるい落とすと考える。差別事例も技術の欠陥ではなく、一時的なエラーと解釈する |
| 強い不信型（2人） | **機械的な無関心。** 不平等な現実のデータをコピーするシステムは客観的になりえないと考える。社会的弱者はデータそのものが乏しいので、主流派の基準が標準になってしまうと指摘する |

### 客観性を確保するための工夫

- 質問紙では肯定・否定の文を混ぜ、標準化された5段階尺度を使い、特定の回答に誘導する表現を除いた。
- 面接では研究者の仮説を明かさずに中立的に尋ね、回答はそのまま記録した。

### 主な業務

- 探究テーマの設定と仮説の立案（「アルゴリズムは社会の偏りを学習・増幅し、客観性の外見の下で差別を再生産する」）
- 文献調査と教科の概念（客観的態度・間主観性、情報格差、批判的犯罪学）との接続
- 質問紙18問・面接項目の設計、データ収集、統計分析とタイプ分類
- 量的・質的な結果と文献を突き合わせた解釈、レポート（11ページ）の作成

## 4. 成果と結果 (Results & Metrics)

### 定量的成果

<p align="center"><img src="../assets/kr/AGDecision/findings.png" width="95%" alt="認識に関する設問と領域ごとの信頼度"></p>
<p align="center"><sub>レポートの数値をもとに描き直したグラフ。左は客観性・信頼に比べて理解度が低い「ブラックボックス信頼」、右は再犯予測が採用・融資・入試より高い「高リスクの委任」</sub></p>

| パターン | 根拠 |
|---|---|
| ① 理解するほど信頼しなくなる | コーディング経験者（5人）は理解度4.0 · 信頼度2.8、未経験者（10人）は理解度1.8 · 信頼度4.1。理解度と信頼度の相関係数は−0.26。マン・ホイットニーのU検定：理解度の差はp = 0.013（有意）、信頼度の差はp = 0.152（方向は同じだが有意でない） |
| ② わからないまま信じる | 「AIは客観的だ」4.13、「信頼できる」3.67、「動作の過程を理解している」2.53 |
| ③ 高リスクの決定まで任せる | 領域ごとの信頼度：コンテンツのおすすめ4.40 > 再犯予測3.73 > 採用3.27 > 融資3.20 > 入試3.00 |
| ④ 客観 ≠ 公正 | 「客観的だ」4.13に対して「公正だ」3.07。15人中6人が、客観性を公正性より2点以上高く評価した。「差別的なら修正されるべきだ」は3.73（6人が5点） |

| 項目 | 結果 |
|---|---|
| 差別の可能性の認識 / 不公正を直接経験した人数 | 3.53 / 5人 |
| 自由回答 | 信頼の理由は4系統（一貫性、統計的な合理性、処理能力、データへの信頼）、不信の理由は5系統（不透明性、誤情報、責任の不在、文脈・倫理の欠如、悪用の可能性） |
| 実技評価の点数 | （要確認） |

### 定性的成果

- **4つのパターンを面接と文献でクロスチェックした。** 理解するほど信じなくなるパターン（①）は、コーディング中級者の面接協力者による「細かいロジックはブラックボックス」という発言と噛み合う。そこから、オニールの言うアルゴリズムの不透明性が、認識の側では「わからないからこそ信じる」信頼（②）として現れる、という解釈につながった。
- **「データが多ければ公正だ」という論理の穴を、教科書の事例で突いた。** 1000万人を調査しながら予測を外した『リテラリー・ダイジェスト』の事例は、標本から低所得層が抜け落ちていたことが原因だった。強い信頼型の論理をデータの代表性の問題で反論し、Gender Shadesの過小代表によるエラーと結びつけた。
- **信頼と不信の根拠は性質からして違うことを見いだした。** 信頼の理由は「一貫性・効率・統計」という漠然とした期待であり、不信の理由は「不透明性・文脈の欠如」という具体的な観察だった。
- **対策を3つの方向で提示した。** アルゴリズムリテラシー教育、高リスク領域での説明可能性と人間による最終確認の義務化、学習データの代表性の確保と差別影響評価である。

### 確認された限界

- **標本が同学年の男子生徒15人だけである。** 性別や階層による差別を扱う探究なのに、標本そのものが一方に偏っているので、結論を一般化しにくい。
- **認識しか測っていない。** 実際のアルゴリズムの出力に含まれる差別は直接測定せず、文献の事例で補った。
- **パターン①は傾向にとどまる。** コーディング経験者が5人しかおらず、信頼度の差は有意ではなかった。
- 提出版の参考文献[2](社会・文化 教科書)は、著者・出版社・年が空欄のままになっている。（要確認）

## 5. トラブルシューティング (Troubleshooting)

### ① 5人と10人を比べる方法が必要だった

**問題** コーディング経験の有無で分けると、一方が5人、もう一方が10人になる。5段階尺度の回答なので、分布も正規分布からかけ離れている。

**原因** 平均だけを比べると、数人の極端な回答で結果が大きくぶれる。標本が小さく、正規性も仮定しにくかった。

**解決** まずクロス集計で集団ごとの回答分布を突き合わせ、2集団の差は順位にもとづくノンパラメトリック検定であるマン・ホイットニーのU検定で確かめた。

**結果** 理解度の差は有意で（p = 0.013）、信頼度の差は方向が同じだけで有意ではなかった（p = 0.152）。クロス表では、経験者の半数以上が低い信頼を、未経験者の80%が高い信頼を示した。

### ② 望んでいた結論が統計的に確定しなかった

**問題** 仮説に最もよく合うパターン①（「理解するほど信頼しなくなる」）の核心である信頼度の差が、有意水準に届かなかった。

**原因** 経験者の標本が5人なので、差があっても検出力が足りない。

**解決** 結論のトーンを下げた。パターン①は「確定した結果」ではなく「標本を増やして改めて確かめるべき傾向」と書き、相関係数（−0.26）と面接での発言を補助的な根拠として添えた。限界の節にも別途記した。

**結果** 検定で確認できたこと（①の理解度の差）、平均の比較にとどまること（②③④）、傾向にとどまったこと（①の信頼度の差）を区別して読めるようになった。

### ③ 認識調査だけでは「実際に差別しているか」を言えなかった

**問題** 仮説は「アルゴリズムが差別を再生産する」なのに、質問紙と面接が測れるのは人々の認識だけである。

**原因** 高校生が採用や再犯予測のアルゴリズムの出力を直接手に入れて測る方法はない。

**解決** 役割を分けた。出力の差別はCOMPAS、Gender Shades、アマゾンの採用の事例で補い、この探究は「その差別がなぜ受け入れられるのか」を認識の次元で説明することに集中した。今後の課題として、HowToのモデルで学習画像の多い種類と少ない種類の誤認識率を比べ、「データが少ない対象ほど間違えやすい」ことを技術の次元で確かめる実験を設計した。

**結果** 仮説の検証範囲を「認識と態度の次元」と明示し、出力の次元は文献と今後の実験に委ねた。

## カスタマージャーニーマップ (Journey Map)

ここでの「ユーザー」は、アルゴリズムの判定を受ける一般市民である。面接のタイプと質問紙の結果をもとに、1人の人がアルゴリズムを受け入れていく過程を再構成した。

| 段階 | 行動 | 考え | 探究で確認したこと |
|---|---|---|---|
| 接触 | おすすめ系のサービスを1日3時間以上使う | 「便利だし、よく合う」 | コンテンツのおすすめへの信頼度4.40 |
| 一般化 | おすすめでの経験をほかの領域に広げる | 「機械なんだから客観的だろう」 | 「客観的だ」4.13、「理解している」2.53 |
| 委任 | 人を判定する決定も任せる | 「人間よりはましだろう」 | 再犯予測は3.73で、採用・融資・入試より高い。部分信頼型の消去法的な信頼 |
| 亀裂 | 差別事例に触れる | 「一時的なエラーだろう」／「もともとそういう構造だ」 | 強い信頼型はエラーとして、強い不信型は構造として解釈 |
| 要求 | 是正を求める | 「差別なら直すべきだ」 | 「修正されるべきだ」3.73、6人が5点 |

## DREAD 脆弱性管理 (DREAD Risk Assessment)

探究で扱った「高リスク領域への委任」をDREADで整理した。スコアは、探究の結果と文献の事例をもとにした定性的な評価である。

| 脅威 | D | R | E | A | D | スコア | 対応（探究からの提言） |
|---|---|---|---|---|---|---|---|
| 再犯予測における集団ごとの誤分類（COMPAS） | 3 | 3 | 2 | 3 | 2 | 2.6 | 説明可能性の確保、人間による最終確認の義務化 |
| 採用モデルによる過去の偏りの再生産（アマゾンの事例） | 3 | 3 | 2 | 2 | 2 | 2.4 | 学習データの代表性の点検、事前・事後の差別影響評価 |
| 理解なき信頼による検証の不在（ブラックボックス信頼） | 2 | 3 | 3 | 3 | 1 | 2.4 | アルゴリズムリテラシー教育 |

<sub>D・R・E・A・D = 被害・再現性・悪用の難易度・影響範囲・発見可能性（1〜3）。スコアは平均。</sub>
