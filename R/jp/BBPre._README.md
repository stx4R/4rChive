# BBPre.

<p align="center"><img src="../assets/kr/BBPre/cover.png" alt="BBPre. 代表画像" width="100%"></p>

> KBO・MLBの試合データで「どんな試合に観客が集まるのか」を予測した機械学習の探究。2026年前半戦を完全に切り離した時間的ホールドアウトで検証し、満員が当たり前になったシーズンで予測問題の性質が変わる地点（打ち切り）を見つけた

---

## 1. プロジェクト概要 (Overview)

| 項目 | 内容 |
|---|---|
| プロジェクト名 | BBPre.（KBO & MLB 観客数予測） |
| 一行要約 | Gradient Boosting 3種とアンサンブル2種で試合ごとの観客数を予測した。KBO 2026年前半戦でTest R² 0.671、MAE 2,418人。ホームチームの人気度は直近の成績の2倍以上強い変数だった |
| 期間 | 2026.03.10 〜 2026.07.13 |
| 参加人数 | 個人での探究 |
| 本人の役割 | 問題設定、データ収集・前処理、特徴量エンジニアリング、モデリング、結果分析、レポート（25ページ）・発表資料の作成 |
| 貢献度 | 100% |
| 実施の経緯 | 2年生の教科外活動（DDC。活動の位置づけは要確認） |

2026年のKBOは、前半戦424試合で763万3,775人（1試合あたり18,004人）を集め、前半戦の最多観客記録を打ち立てた。観客数はチケット売上だけでは終わらず、球場のF&B、マーチャンダイジング、スポンサーシップ、放映権の交渉力にまでつながる。しかし「観客が多い」という事実だけでは何も決められない。どんな試合に、どんな要因で人が集まるのか、満員の裏にどれだけの需要が隠れているのかがわかって初めて、価格・マーケティング・人員配置・球場の増築をデータで判断できる。

**研究課題。** 観客数は単純な時系列のトレンドなのか、それとも天候・ライバル戦・順位・人気度が絡み合った、試合ごとの条件の関数なのか？

| 仮説 | 内容 | 確認方法 |
|---|---|---|
| 1. イベントの相互作用 | 試合ごとの条件を入力とする回帰モデルがR² 0.6以上を出す | テストR² |
| 2. ブランドの優位 | 短期的な成績より、長年積み上げた球団の人気度のほうが強い予測変数である | 特徴量重要度の順位 |
| 3. 汎化 | 2023–2025で学習したモデルが2026年前半戦でも崩れないが、満員による上限の分だけ性能が落ちる | 既存の分割と比べた変化幅、残差のパターン |

> **データについて。** 元のレポートの限界の節に書いたとおり、試合単位の詳細データの一部は、公開されている集計値（前半戦424試合、総数763万人、球団別の平均観客数・占有率）に合わせて補正した**生成データ**である。以下の性能の数値は、これにもとづく推定値である。実測の試合単位データが手に入れば、同じパイプラインで計算し直す必要がある。

## 2. 技術スタック (Tech Stack)

| 区分 | 技術 | 選定理由 |
|---|---|---|
| モデル | XGBoost、LightGBM、CatBoost | 表形式のデータで、非線形の相互作用（猛暑 × 屋外球場など）をうまく捉える。3方式の性格の違いも比べられる |
| アンサンブル | Voting（単純平均）、Stacking（Ridgeのメタモデル） | 単一モデルの偏りを互いに打ち消す |
| 検証 | 時系列順を保ったCV（チューニング）、2026年前半戦の時間的ホールドアウト（最終評価を1回だけ） | ランダムに分割すると、未来の情報で過去を当てるリークが起きる |
| データ | KBO公式・NAVERスポーツ、韓国気象庁の気象データ開放ポータル、MLB Stats API・pybaseball、Retrosheet形式のゲームログ | 試合・天候・セイバーメトリクスを1試合単位で結合する |
| 指標 | R²、MAE、RMSE、過学習ギャップ（Train R² − Test R²） | MAEは「何人外れるか」としてそのまま読め、ギャップは新しいシーズンへの汎化能力を示す |

## 3. 主な機能と担当業務 (Key Features & Contributions)

### データ

| データ | 期間 | 規模 |
|---|---|---|
| KBOの試合記録 | 2023 〜 2026年前半戦 | 2,584試合（学習2,160 · テスト424） |
| 気象 | 2023 〜 2026 | 試合日 × 球場の観測所の対応付け（気温・降水・湿度・風速・雲量） |
| MLBの試合記録 | 2020 〜 2026年前半戦 | 14,456試合（学習13,046 · テスト約1,410） |
| MLBのゲームログ | 2020 〜 2026 | 28,912チーム-試合 |

- 気象データの欠損は近隣の観測所の値か月平均で埋め、観客数のない試合は除外した。
- 雨天ノーゲーム、サスペンデッド、開幕戦、こどもの日のような特殊な試合には別途フラグを付けた。
- ドーム球場（高尺）は、ドームのダミー変数との相互作用で天候の影響を切り分けた。MLBの2020年（60試合の短縮シーズン、無観客を含む）は除外するかダミー変数で処理した。
- カテゴリ変数は、CatBoostでは組み込みの処理に任せ、XGBoost・LightGBMではLabel/One-hotでエンコードした。リークのおそれがあるターゲットエンコーディングは使わなかった。

### 特徴量エンジニアリング

原則は1つだけだった。**試合開始前にマーケティング担当者が知りうる情報しか使わない。**

| 分類 | 特徴量 |
|---|---|
| 環境 | 不快指数 `DI = 9/5·T − 0.55·(1 − RH/100)·(9/5·T − 26) + 32` |
| 日程 | `is_weekend`、`is_holiday`、`holiday_weight` |
| シーズン | `season_progress`、`race_intensity = 進行率 × ホームチーム勝率` |
| モメンタム | `home_recent10_wr = rolling_mean(win, 10).shift(1)` |
| 人気度 | `home_pop / away_pop = expanding_mean(attendance).shift(1)` |
| 球場 | `capacity`、`is_dome` |
| ライバル戦 | 蚕室ダービー、「エルロッラシコ」（LG対ロッテ）、クラシックシリーズ、錦江シリーズの二値フラグ |

### モデリング

- ハイパーパラメータは、学習区間の中で時系列順を守ったCVで探した（木の深さ4–8、学習率0.03–0.1、木の数300–1,200、サブサンプル0.7–1.0）。テストセットは最終評価に1回だけ使った。
- KBOとMLBに同じパイプラインを回し、結果がリーグをまたいで再現されるかを見た。
- MLBのゲームログから、チーム-シーズン単位のOPS、wRC+、WAR、BABIP、ISO、ピタゴラス勝率を計算し、観客モデルとの関係を別に分析した。

### 主な業務

- KBO・MLB・気象データの収集と試合単位での結合、前処理ルールの策定
- リークのない特徴量の設計（`shift(1)`、expanding mean）と、時系列ソートの単調性の検証
- 5つのモデルの学習・チューニング・比較、特徴量重要度・残差の分析、ソウル3球団の年度別分析
- セイバーメトリクスへの分析の拡張、レポートと発表資料の作成

### 定性的成果

- **ブランドが成績に勝つ。** 観客動員は、今週の順位争いよりも、何年もかけて積み上げたファン基盤の関数だった。再建期のシーズンでもファン体験への投資を削ってはいけない、という根拠になる。
- **CatBoostの安定性が2つのリーグで再現された。** KBOでは過学習ギャップが最も小さく、MLBでは単一モデルでアンサンブルを上回った。XGBoostは学習時の性能こそ最上位だったが、ギャップが0.276と、新しいシーズンへの汎化に最も弱かった。
- **精緻なセイバー指標は、観客モデルでは弱かった。** チームのOPSと得点は強く結びつき、出塁率のほうが長打率よりも得点に大きく寄与していた。しかし、これらの指標を観客モデルに入れると重要度は低く出た。ファンはwRC+よりも順位・連勝・スター選手といった目に見えるシグナルに反応し、チームの実力は長期的な人気度を経由して興行につながる、と解釈した。
- **MLBの誤差が大きい理由を構造から説明した。** 平均約2.8万人に対してRMSE 6,941人は大きいほうだが、これは30球団・球場の異質性が、10球団のKBOよりはるかに大きいためである。

### 確認された限界

- **一部の試合データが生成データである。** 性能の数値は実測ではなく、補正データにもとづく推定値である。元データとコードはローカルに残っていない。（要確認）
- **打ち切りは診断しただけで、解決はしていない。** 満員の試合の潜在需要を推定するには、Tobit回帰や打ち切りを考慮した損失関数のような方法が必要になる。
- **2026年は前半戦しか反映していない。** 後半戦の順位争いとポストシーズンを含めた、フルシーズンでの再検証が必要である。
- **チケット価格の変数がないため、** 価格弾力性を推定できなかった。

## 5. トラブルシューティング (Troubleshooting)

### ① ランダムに分割すると性能が水増しされる

**問題** 観客データには時間の順序がある。学習とテストをランダムに分けると、モデルが未来の試合の情報を使って過去を当てることになる。直近の勝率や人気度のような動的な変数には、その試合自体の結果が紛れ込む。

**原因** リークは2つの層で起きる。特徴量の側では「その試合まで含めた」勝率・平均観客数が、評価の側ではテストより後の試合が、学習に入り込んでしまう。

**解決** 二重に防いだ。特徴量については、すべての動的変数に`shift(1)`をかけ、その試合**より前**の情報だけを使うようにした。並び順が崩れると`shift`が無意味になるので、試合日時の単調性をコードで検証した。評価は2023–2025で学習、2026年前半戦でテストと時間で完全に分け、チューニングも学習区間内の時系列順CVだけで行った。

**結果** 既存の分割での0.697より低い0.671になった。この差を性能の低下ではなく、「リークのない汎化性能と、過去を再現する能力との差」と読んだ。高いR²よりも、どんな条件で測ったかのほうが先だ、というのが結論である。

### ② 満員が増えると、モデルが「需要」ではなく「座席」を学び始めた

**問題** 2026年前半戦で性能が落ち、収容人数の特徴量重要度が18.3%から20.4%に跳ね上がった。ソウル3球団のR²もすべて下がった。

**原因** 観測される観客数は`min(需要, 収容人数)`である。満員の試合では、本当の需要が収容人数で打ち切られて見えなくなる。すると観客数の分散そのものが小さくなって「説明すべき分散」が消え、予測問題が需要の予測から供給制約の予測へと変わってしまう。

**解決** 残差を球団・曜日・占有率の区間ごとに分解し、打ち切りの痕跡を探した。ハンファのホームゲームの残差は、系統的に負（予測 > 実際の上限）に偏っていた。条件だけを見ればモデルは収容人数以上を予測するが、実際の値は上限で打ち切られている。逆に、月曜の移動日明けの火曜の試合では残差が正に偏っており、モデルが平日の効果を過大に反映していることもわかった。

**結果** ハンファは平均観客数が中位なのに占有率はリーグ最高で、座席を増やせば埋まるだけの需要があるという根拠が得られた。観客モデルはマーケティングの道具にとどまらず、座席の増設のような投資判断の出発点にもなりうる、という結論に至った。潜在需要の大きさを直接推定するTobit系の方法は、今後の課題として残した。

### ③ 気温だけでは夏の観戦の不快さを表しきれない

**問題** 真夏の屋外球場で観客が伸び悩むのは、気温だけの問題ではない。同じ気温でも、湿度によって体感の暑さは大きく変わる。ドーム球場はそもそも天候の影響を受けない。

**原因** 気温と湿度を別々に入れると、モデルが両者の組み合わせの効果を自力で見つけなければならず、ドームと屋外球場を同じルールで扱うことにもなる。

**解決** 気温（`T`）と湿度（`RH`）を組み合わせた不快指数を派生変数として加え、ドーム球場はドームのダミー変数との相互作用で天候の効果を切り分けた。

**結果** 不快指数は重要度4位（11.2%）だった。木モデルは、DIが80を超える猛暑の区間で屋外球場の観客が伸び悩むという非線形のパターンを捉えた。

<details>
<summary><b>用語</b></summary>

- **時間的ホールドアウト**：学習とテストを時間の順に分け、未来のデータだけで評価する方式
- **データリーク**：予測時点では知りえない情報が学習に使われ、性能が水増しされる現象
- **打ち切り（Truncation）**：観測値が上限・下限で打ち切られ、本当の値がわからない状態（満員の試合の観客数）
- **Tobitモデル**：打ち切られた従属変数の潜在値を推定する計量経済モデル
- **過学習ギャップ**：Trainでの性能とTestでの性能の差
- **Ordered Boosting**：ランダムな順序の中で、各サンプルより前にあるサンプルだけを使ってそのサンプルの残差を計算し、リークを減らすCatBoostの学習方式
- **Expanding Mean**：時点*t*までのすべての過去の値の平均。累積したファン基盤の代理指標

</details>

## カスタマージャーニーマップ (Journey Map)

この探究における「顧客」は、モデルを使う球団のマーケティング担当者である。

| 段階 | 行動 | 考え | モデルが提供するもの |
|---|---|---|---|
| シーズン前 | ホームゲームの日程を受け取る | 「どの試合に力を入れるべきだろう？」 | 曜日・祝日・ライバル戦・相手の人気度から出した試合ごとの予想観客数 |
| 試合の週 | 天気予報を確認する | 「猛暑になったら、どれくらい減るだろう？」 | 不快指数を反映した予測、1試合あたりの誤差は約2,400人 |
| 試合当日 | 売店の在庫・警備の人員を配置する | 「何人を想定して準備すればいい？」 | MAE 2,418人程度の精度による人員計画の根拠 |
| シーズン中 | 成績が落ちる | 「観客も減るだろうな」 | 直近の勝率よりも人気度のほうが2倍以上強いという根拠 |
| シーズン後 | 増築・価格を検討する | 「座席を増やしたら埋まるだろうか？」 | 満員の球団の負の残差から見える潜在需要の存在 |
