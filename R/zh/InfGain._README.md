# InfGain.

<p align="center"><img src="../assets/InfGain/cover.png" alt="InfGain. 封面图" width="100%"></p>

> 用 Play Tennis 的14个样本手算全部熵与信息增益，验证高中对数函数如何让决策树选出“最好的问题”的代数探究。结果做成了用颜色标示熵的立体树模型

---

## 1. 项目概述 (Overview)

| 项目 | 内容 |
|---|---|
| 项目名称 | InfGain.（对数函数与决策树的信息增益） |
| 一句话概述 | 从香农熵 → 信息增益 → 完成 ID3 树，全程手算，证明了信息增益最大的 Outlook（0.246）成为根节点，Sunny 再按 Humidity 分裂，Rain 再按 Wind 分裂。提出了从根到叶的“累计信息增益”这一自创指标 |
| 进行时间 | 2026.06（高二代数 D.D.I.M.-O.P. 第3课时） |
| 参与人数 | 个人探究 |
| 本人角色 | 选题、背景调查、全过程手算、立体模型设计与制作、撰写报告（8页） |
| 贡献度 | 100% |

在之前的 HIU 探究中，我了解到二分查找的最大查找次数是 `log₂N`。由此我对对数产生了兴趣：它不仅能表示效率，在人工智能算法中也起着核心作用。决策树是广泛用于垃圾邮件过滤、医疗诊断、信用评估的基础算法，而在决定按什么标准划分数据的计算中，用到的正是高中的对数函数。

**研究问题。** 决策树选择“最好的问题”的标准是什么？这个标准源自对数函数的哪种性质？

| 假设 | 内容 |
|---|---|
| 1. 分裂效率 | 越是选择信息增益最大的特征作为根节点，就能用越少的分裂准确地对数据分类 |
| 2. 对数的性质 | 在 `H = −Σ p log₂ p` 中，数据只由一类构成时熵为0，两类各占一半时熵取最大值（1比特） |

## 2. 技术栈 (Tech Stack)

这是手算探究，因此这里列出的不是工具，而是数学概念和资料。

| 类别 | 内容 | 用途 |
|---|---|---|
| 香农熵 | `H(X) = −Σ p(xᵢ) log₂ p(xᵢ)` | 以比特为单位衡量节点的不纯度（混杂程度） |
| 信息增益 | `IG(S, A) = H(S) − Σ (\|Sᵥ\|/\|S\|) · H(Sᵥ)` | 根据分裂前后熵减少了多少来衡量问题的好坏 |
| ID3 (Quinlan, 1986) | 选出信息增益最大的特征，并在子节点中重复这一过程 | 递归地构建出完整的树 |
| 数据 | Play Tennis（Mitchell，*Machine Learning* 第3章）14个样本，Yes 9 / No 5 | 4个特征：Outlook · Temperature · Humidity · Wind |
| 模型 | 球·牙签立体模型，Blender 模型 | 用颜色表示熵，用标签表示累计信息增益 |

**以2为底的原因。** 因为熵可以解读为“要对一个样本分类，平均需要问几次是/否问题”。确定为一类时无需提问，`H = 0`；各占一半时需要问一次，`H = 1比特`。这与 HIU 探究中二分查找每次把候选减半、`log₂n` 次就找到答案是同一个原理。

## 3. 核心功能与负责工作 (Key Features & Contributions)

### 计算步骤

1. 计算全部数据的根节点熵 `H(S)`
2. 分别计算4个特征的信息增益 → 选择最大的特征作为根节点
3. 在根节点的每个分支上用剩余特征重复同样的计算，完成整棵树
4. 确认所选结构是否以最少的分裂完成数据分类

**根节点。** Yes 9 · No 5，因此 `H(S) = −(9/14)log₂(9/14) − (5/14)log₂(5/14) ≈ 0.940`。接近1，不纯度高。

| 特征 | 各分支（Yes : No → H） | 信息增益 |
|---|---|:---:|
| **Outlook** | Sunny 2:3 → 0.971 · Overcast 4:0 → **0** · Rain 3:2 → 0.971 | **0.246** |
| Humidity | High 3:4 → 0.985 · Normal 6:1 → 0.592 | 0.151 |
| Wind | Weak 6:2 → 0.811 · Strong 3:3 → **1.000** | 0.048 |
| Temperature | Hot 2:2 → **1.000** · Mild 4:2 → 0.918 · Cool 3:1 → 0.811 | 0.029 |

**第二次分裂。**

| 分支 | 剩余特征的信息增益 | 选择 |
|---|---|---|
| Sunny (2:3, H = 0.971) | Humidity **0.971** · Temperature ≈ 0.571 · Wind ≈ 0.020 | Humidity（High → 全部 No，Normal → 全部 Yes） |
| Rain (3:2, H = 0.971) | Wind **0.971** · Humidity 0.020 · Temperature ≈ 0.020 | Wind（Weak → 全部 Yes，Strong → 全部 No） |

```
                     [ Outlook ]  H=0.940, IG=0.246
                    /      |      \
              Sunny/   Overcast    \Rain
                  /         |        \
         [ Humidity ]     YES      [ Wind ]
          H=0.971         H=0       H=0.971
          IG=0.971      (n=4)       IG=0.971
          /      \                  /     \
      High      Normal          Weak      Strong
       |          |               |         |
      NO         YES            YES        NO
```

### 立体模型

<p align="center"><img src="../assets/InfGain/model.png" width="90%" alt="决策树立体模型渲染图"></p>
<p align="center"><sub>渲染了本地保存的 Blender 模型（底座上的姓名、学号文字已隐藏）。红球是需要继续分裂的内部节点，蓝球是已完全归为一类的叶节点</sub></p>

| 模型元素 | 对应 |
|---|---|
| 球 / 牙签 | 节点 / 分裂 |
| 红球 | 熵 > 0：尚未完成分类的内部节点 |
| 蓝球 | 熵 = 0：已完全归为一类的叶节点 |
| 节点标签 | 特征名、该节点的 `H`、该位置的 `IG` |
| 叶标签 | 到达的样本数 `n`、从根开始的**累计信息增益** |

与平面图示相比，有两点不同。一是把节点的熵涂成红色或蓝色，让不纯度和是否完全分类一目了然。二是不写各节点的信息增益，而是写出从根到叶的信息增益之和，从而可以直接比较每条路径达到完全分类所需的总信息量和深度。

### 主要工作

- 整理熵、信息增益、ID3 的背景，解释以2为底的含义（与二分查找的联系）
- 手算从根节点到第二次分裂的全过程，编制熵速查表
- 设计累计信息增益指标，设计并制作立体模型
- 撰写报告

## 4. 成果与结果 (Results & Metrics)

### 定量成果

| 路径 | 分裂次数 | 累计信息增益 | 到达 |
|---|:---:|:---:|---|
| Overcast | **1次** | **0.246** | 蓝色叶节点（Yes，n = 4） |
| Sunny → Humidity | 2次 | 1.217 | 蓝色叶节点（No / Yes） |
| Rain → Wind | 2次 | 1.217 | 蓝色叶节点（Yes / No） |

| 项目 | 结果 |
|---|---|
| 假设1 | 得到支持。把信息增益最大的 Outlook 作为根节点后，Overcast 分支（4个）一次就完成分类，其余两个分支也只需再分一次，所有叶节点的熵都变为0 |
| 假设2 | 得到支持。只由一类构成的 Overcast · Rain-Weak · Rain-Strong 为 `H = 0`，各占一半的 Wind-Strong · Temperature-Hot 为 `H = 1.000` |
| 代码重算（2026.09） | 树结构和排序与手算相同。根节点的信息增益为 Outlook 0.247、Humidity 0.152，与手算结果（0.246、0.151）在第三位小数上各差1（见下文 §5-③） |
| 表现性评价分数 | （待确认） |

**熵速查表（Yes : No）**

| 构成 | 0 | 6:1 | 3:1 · 6:2 | 4:2 | 9:5 | 2:3 · 3:2 | 3:4 | 2:2 · 3:3 |
|---|:---:|:---:|:---:|:---:|:---:|:---:|:---:|:---:|

### 定性成果

- **通过计算确认了熵公式本身就是对数函数。** 对数的性质与“只有一类时为0、各占一半时最大”这一不纯度度量的性质恰好吻合。
- **开始把对数理解为衡量不确定性的工具，而不是加快计算的函数。** 把以2为底读作“提问次数”，二分查找和决策树就能用同一种语言联系起来。
- **亲手体会到了“AI 在学习”的实质。** 那是一个在每次分裂时比较熵、反复做出信息量最大的选择的数学过程。

### 已知局限

- **这是只有14个样本的教科书例题。** 没有涉及连续型特征、缺失值和过拟合。
- **没有与其他分裂标准进行比较。** 与 CART 的基尼不纯度、C4.5 的信息增益率的比较留作后续课题。
- **Blender 模型中 Wind 节点的标签是 `IG=0.048`。** 这个值是从根节点看 Wind 的信息增益，而在 Rain 分支中 Wind 的信息增益是0.971。实物模型上是否用了同样的标签（待确认）
- **Blender 模型的图例把红色写成“熵0.9以上”。** 这与报告中的定义（熵 > 0）不同。不过这棵树的内部节点熵都在0.94以上，因此结果相同。

## 5. 问题排查经验 (Troubleshooting)

### ① 光看数字，看不出假设在树中如何体现

**问题** 用表格算完所有熵和信息增益后，数字太多，也太抽象。很难确认“越是把信息增益大的特征放在根节点，分裂就越少”这一假设在树结构中实际呈现为什么样子。

**原因** 表格只是把各特征的值并排列出，并不显示这些值能让树的哪条分支多快结束。

**解决** 不画平面图示，而是做了立体模型。用球表示节点、牙签表示分裂，把熵为0的叶节点涂成蓝色，仍然混杂的内部节点涂成红色。

**结果** 仅凭颜色就能看出：Overcast 分支一次就到达蓝色叶节点，而 Sunny 和 Rain 要再经过一个红色节点才能到达蓝色叶节点。

### ② 只靠各节点的信息增益，无法在路径之间比较

**问题** 标准的决策树图只在每个节点上写出该处的信息增益。靠这个无法比较“哪条路径完成分类需要更多信息”。

**原因** 信息增益是一次分裂的效果，整条路径的代价需要人在脑中自行相加。

**解决** 在每个叶节点上写出从根到该叶的信息增益之和，即“累计信息增益”。

**结果** Overcast 0.246（1次）对 Sunny·Rain 1.217（2次），用一个数字就能比较各路径的深度和所需信息量。

### ③ 手算与代码计算在第三位小数上不一致（再验证）

**问题** 写这份报告时，我用代码重新计算了同一份数据，得到根节点的信息增益为 Outlook 0.247、Humidity 0.152，而手算值是0.246、0.151。

**原因** 手算时是用各分支熵在第三位小数四舍五入后的值（0.971、0.985 等）来求加权和的。中间值的舍入误差累积到了最后一位。

**解决** （记录于报告 v2.0）确认对排序和树结构没有影响，并把两个值一并写出。手算时只要中间值多保留一位、最后再四舍五入即可。

**结果** Outlook > Humidity > Wind > Temperature 的顺序以及第二次分裂（Humidity、Wind），手算与代码完全一致。

<details>
<summary><b>术语</b></summary>

- **信息量 `I(x) = log₂(1/p)`**：事件概率越低，该值越大
- **香农熵**：信息量的期望值。以比特为单位衡量数据的不纯度
- **比特**：相当于一次是/否提问的信息单位
- **信息增益（IG）**：分裂前后熵的减少量。越大说明问题越好
- **ID3**：1986年由罗斯·昆兰（Ross Quinlan）提出、用信息增益递归构建树的算法
- **根 / 内部 / 叶节点**：树的起点 / 还需继续划分的节点（H > 0）/ 分类已完成的节点（H = 0）
- **累计信息增益**：从根到叶各次分裂的 IG 之和。本探究的自创指标
- **基尼不纯度 / 信息增益率**：分别为 CART、C4.5 使用的分裂标准
